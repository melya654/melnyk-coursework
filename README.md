# SecureForms — безпека веб-форм

Демонстраційний проєкт до курсової роботи: валідація, захист від спаму та некоректного введення даних.

## Запуск
```
npm install
npm start        # http://localhost:3000
npm test         # 21 автотест атак і валідації
```
Потрібен Node.js 22+. У продакшні задайте змінні `NODE_ENV=production` і `FORM_SECRET`.

## Рівні захисту
| Рівень | Що робить | Файл |
|---|---|---|
| Клієнтська валідація | миттєві підказки, доступні повідомлення | public/js/forms.js |
| Серверна валідація | allowlist, нормалізація, типи, межі | src/validators.js |
| Антиспам | honeypot, мінімальний час заповнення, rate limit, ліміт запитів відновлення на email | src/security.js, src/server.js |
| CSRF | HMAC-токен форми, привʼязаний до cookie сесії | src/security.js |
| XSS | allowlist + екранування + CSP | src/security.js, helmet |
| SQL-ін'єкції | параметризовані запити | src/db.js |
| Паролі | scrypt із випадковою сіллю | src/db.js |

## Форми
| Сторінка | Файл | Що перевіряється |
|---|---|---|
| Вхід | public/index.html | формат email, однакова відповідь при помилці, постійний час перевірки пароля |
| Реєстрація | public/signup.html | імʼя, прізвище, email, телефон +380, країна зі списку (allowlist), пароль |
| Відновлення пароля | public/forgot.html | формат email, однакова відповідь, ліміт 3 запити на год. на адресу |

Макет: Authentication UI Design Kit (Mo Hady, Bitjam.co), Figma Community. Ліцензію й посилання вказати в записці.
Сесії, токени скидання й надсилання листів у проєкті навмисно не реалізовані: це виходить за межі теми.

## Публікація на Vercel
1. Імпортувати GitHub-репозиторій у Vercel (Add New → Project).
2. У Settings → Environment Variables додати `FORM_SECRET` (довгий випадковий рядок) і `NODE_ENV=production`.
3. Deploy.

Обмеження: на Vercel база SQLite лежить у `/tmp` і не зберігається між запусками, а лічильник
rate limit працює окремо в кожному екземплярі. Для реального проєкту потрібна зовнішня БД і сховище лічильників.
